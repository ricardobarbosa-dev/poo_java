PEQUENO

1. Classe, objeto e construtor

Classe é o molde. Objeto é cada coisa criada a partir dele: "Jogador" é a classe; Gabigol e Pedro são objetos. O que o objeto tem são atributos; o que ele faz são métodos.

public class Jogador {
    private String nome;
    private int gols;

    public Jogador(String nome) {
        this.nome = nome;
    }

    public void marcarGol() {
        gols++;
    }
}

Linha a linha

  • 1Declara a classe. public = qualquer parte do código pode usar. O nome começa com maiúscula e é igual ao do arquivo.
  • 2-3Atributos: os dados do jogador. String guarda texto, int guarda número inteiro (começa em 0). private esconde de fora da classe.
  • 5Construtor: tem o mesmo nome da classe e não tem tipo de retorno. Roda sozinho quando você usa new.
  • 6this significa "este objeto". this.nome é o atributo; nome sozinho é o parâmetro recebido.
  • 9Método: uma ação. void = não devolve nada.
  • 10gols++ soma 1 ao atributo.
Jogador gabigol = new Jogador("Gabigol");
gabigol.marcarGol();
  • 1Cria um objeto: tipo, nome da variável, new chama o construtor.
  • 2O ponto manda o objeto agir: "Gabigol, marque um gol".

Quando usar: sempre que várias coisas do mesmo tipo têm os mesmos dados e ações (jogadores, times, estádios).

FUNDAMENTOS

2. Construtor, getter e setter

O que é: o construtor monta o objeto; o getter deixa ler um atributo; o setter deixa alterar um atributo.

Para que serve: como os atributos são private, esses três são as portas oficiais para criar, ler e mudar os dados.

public class Jogador {
    private String nome;
    private int camisa;
    private boolean titular;

    public Jogador() {
        this("Sem nome", 0);
    }

    public Jogador(String nome, int camisa) {
        this.nome = nome;
        this.camisa = camisa;
    }

    public String getNome() {
        return nome;
    }

    public void setCamisa(int camisa) {
        this.camisa = camisa;
    }

    public boolean isTitular() {
        return titular;
    }
}

Linha a linha

  • 6-8Construtor vazio. Se você não escrever nenhum, o Java cria um vazio sozinho; no momento em que você escreve um, o automático some. this(...) chama o outro construtor e evita repetir código.
  • 10-13Construtor completo. Dois construtores com o mesmo nome e parâmetros diferentes se chamam sobrecarga: você escolhe como criar o objeto.
  • 15-17Getter: devolve o valor (return). Aqui não há setter de nome: o nome é só de leitura, ninguém troca.
  • 19-21Setter: recebe um valor novo e grava no atributo.
  • 23-25Para boolean o costume é is no lugar de get.
Jogador a = new Jogador();
Jogador b = new Jogador("Pedro", 9);
b.setCamisa(10);
System.out.println(b.getNome());
  • 1-2Cada new escolhe o construtor pelos parâmetros que você passa.
  • 3Muda a camisa pelo setter. 4 lê o nome pelo getter.

Quando usar: construtor sempre que o objeto precisa de dados para existir. Getter só se alguém de fora precisa ler. Setter só se o valor pode mudar, de preferência com validação. Não crie por hábito: no IntelliJ, Alt+Insert gera todos quando precisar.

Desafios

A classe não tem nenhum construtor. O que acontece?

Dá erro de compilaçãoO Java cria um construtor vazio automaticamenteNão dá para criar objetos delaMas se você escrever qualquer construtor, esse automático deixa de existir.

O nome do jogador nunca deve mudar. O que fazer?

Criar só o getter, sem setterCriar getter e setter públicosDeixar o atributo publicSem setter, o atributo vira somente leitura.

3. Encapsulamento

É proteger os dados do objeto: o atributo fica private e só métodos controlam como ele muda. Assim o objeto nunca fica com valor inválido (camisa 500, por exemplo).

public class Jogador {
    private int camisa;

    public void setCamisa(int camisa) {
        if (camisa < 1 || camisa > 99) {
            throw new IllegalArgumentException("Camisa de 1 a 99");
        }
        this.camisa = camisa;
    }

    public int getCamisa() {
        return camisa;
    }
}

Linha a linha

  • 2private: só código de dentro da classe enxerga esse atributo.
  • 4Setter (de "set", definir): o único caminho de fora para alterar a camisa.
  • 5A regra. || significa "ou": camisa menor que 1 ou maior que 99 é inválida.
  • 6throw interrompe com um erro claro, em vez de aceitar dado ruim em silêncio.
  • 8Só chega aqui se passou na regra, então grava com segurança.
  • 11-12Getter (de "get", pegar): deixa ler o valor sem permitir alterar.
Quem enxerga o quê
  • private: só a própria classe.
  • (sem nada): classes do mesmo pacote.
  • protected: mesmo pacote e classes filhas.
  • public: todo mundo.

Vantagens: segurança (ninguém coloca dado inválido), manutenção (você muda o código por dentro sem quebrar quem usa) e regras num lugar só.

Quando usar: sempre. Comece todo atributo como private. Crie getter se alguém precisa ler, e setter só se precisa mudar, com validação.

Desafios

O que é encapsulamento?

Esconder os dados e liberar acesso só por métodos controladosCriar classes filhasRepetir código em vários lugaresO objeto protege seu próprio estado.

Por que o atributo camisa é private?

Para o código rodar mais rápidoPara ninguém de fora colocar um valor inválidoPorque o Java obrigaCom private, toda mudança passa pela validação do setter.

Qual método serve só para LER a camisa?

Qual modificador deixa o membro visível para o pacote e para as classes filhas?

4. Métodos especiais

O que é: métodos que o Java já conhece e chama sozinho em certas situações: toString (texto do objeto), equals (comparar), hashCode (etiqueta numérica) e o main (início do programa).

Para que serve: fazer seus objetos "falarem" a língua do Java: aparecer legíveis no console, ser comparados corretamente e funcionar em listas e conjuntos.

public class Time {
    private String nome;

    public Time(String nome) {
        this.nome = nome;
    }

    @Override
    public String toString() {
        return "Time: " + nome;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Time)) return false;
        Time outro = (Time) o;
        return nome.equals(outro.nome);
    }

    @Override
    public int hashCode() {
        return nome.hashCode();
    }
}

Linha a linha

  • 8-11toString: sem ele, imprimir o objeto mostra algo feio como Time@1b6d3586. Com ele, aparece Time: Flamengo.
  • 14equals recebe qualquer Object, pois você pode comparar com qualquer coisa.
  • 15Se for exatamente o mesmo objeto na memória, é igual.
  • 16instanceof pergunta "isso é um Time?". Se não for, é diferente.
  • 17Converte (cast) o Object para Time, para poder ler o nome.
  • 18Dois times são iguais se têm o mesmo nome. Texto se compara com equals, nunca com ==.
  • 21-24hashCode: objetos iguais pelo equals precisam ter o mesmo número. HashSet e HashMap usam esse número para achar objetos rápido.
Time a = new Time("Flamengo");
Time b = new Time("Flamengo");
System.out.println(a == b);
System.out.println(a.equals(b));
System.out.println(a);
  • 3false: são dois objetos diferentes na memória, mesmo com o mesmo nome.
  • 4true: o conteúdo é igual.
  • 5Imprime Time: Flamengo: o Java chamou o toString sozinho.
E o main? public static void main(String[] args) é a porta de entrada: o Java começa a rodar o programa por ele. static permite rodar sem criar objeto.

Quando usar: toString em quase toda classe (ajuda muito a depurar). equals e hashCode sempre juntos, quando objetos serão comparados ou guardados em Set/Map. O IntelliJ gera os três com Alt+Insert.

Desafios

Qual a diferença entre == e equals em objetos?

Nenhuma== compara o conteúdo, equals compara o endereço== vê se é o mesmo objeto; equals compara o conteúdoPor isso a e b acima dão false com == e true com equals.

Para que serve o toString?

Dar um texto legível do objeto ao imprimirConverter texto em númeroCriar o objetoEle é chamado automaticamente em println e em concatenações.

Você sobrescreveu equals. O que fazer junto?

Apagar o toStringSobrescrever também o hashCodeNadaRegra do Java: iguais pelo equals devem ter o mesmo hashCode.

RELACIONAMENTO

5. Relacionamento entre classes

O que é: a forma como uma classe se liga a outra.

Para que serve: modelar o mundo real e decidir quem depende de quem. Do vínculo mais fraco ao mais forte:

  • Dependência ("usa"): a classe só usa a outra de passagem, como parâmetro. O Árbitro usa a Partida para apitar.
  • Associação ("conhece"): guarda uma referência como atributo. O Jogador conhece seu Time.
  • Agregação ("tem", parte independente): o todo tem as partes, mas elas existem sem ele. O Time tem Jogadores; se o time fechar, o jogador continua existindo.
  • Composição ("tem", parte dependente): a parte nasce e morre com o todo. A Partida tem Gols; sem a partida, o gol não existe.
  • Herança ("é um"): o vínculo mais forte. Goleiro é um Jogador.
public class Arbitro {
    public void apitar(Partida p) {
        p.encerrar();
    }
}

public class Jogador {
    private Time time;
}

public class Time {
    private List<Jogador> elenco;
    public Time(List<Jogador> elenco) { this.elenco = elenco; }
}

public class Partida {
    private List<Gol> gols = new ArrayList<>();
    public void registrarGol(String autor, int minuto) {
        gols.add(new Gol(autor, minuto));
    }
}

Linha a linha

  • 2-3Dependência: o Árbitro não guarda a Partida. Recebe, usa e esquece.
  • 8Associação: o Jogador guarda uma referência ao seu Time.
  • 12-13Agregação: a lista de jogadores vem pronta de fora, pelo construtor. Eles já existiam antes do Time.
  • 17-19Composição: a própria Partida cria os gols com new. Eles só existem dentro dela.

Truque para decidir: quem cria a parte? Se ela chega pronta de fora, é agregação. Se o todo cria com new lá dentro, é composição. Se o todo só usa a parte de passagem, é dependência. Prefira sempre o vínculo mais fraco que resolve o problema.

Desafios

O Time recebe a lista de jogadores pronta pelo construtor. Qual relacionamento?

ComposiçãoAgregaçãoHerançaOs jogadores existem independentemente do Time.

O Gol é criado dentro da Partida e não existe sem ela. Qual relacionamento?

DependênciaAssociaçãoComposiçãoA parte nasce e morre com o todo.

O Árbitro só recebe a Partida como parâmetro de um método. Qual relacionamento?

DependênciaAgregaçãoHerançaÉ o vínculo mais fraco: usa e esquece.

6. Objetos compostos

O que é: um objeto que carrega, dentro dele, outros objetos como atributos. Como uma boneca russa: o Time tem um Estádio dentro.

Para que serve: quebrar um objeto grande em peças pequenas e reaproveitáveis, cada uma com suas regras.

public class Estadio {
    private String nome;
    private int capacidade;

    public Estadio(String nome, int capacidade) {
        this.nome = nome;
        this.capacidade = capacidade;
    }

    public String getNome() {
        return nome;
    }
}

public class Time {
    private String nome;
    private Estadio estadio;

    public Time(String nome, Estadio estadio) {
        this.nome = nome;
        this.estadio = estadio;
    }

    public String descricao() {
        return nome + " joga no " + estadio.getNome();
    }
}

Linha a linha

  • 1-13Uma classe comum, com seus dados, construtor e getter.
  • 17O tipo do atributo é outra classe. Isso é o objeto composto: o Time tem um Estadio.
  • 19-22O Time recebe o Estadio já pronto e guarda a referência.
  • 25O Time pede o nome ao Estadio pelo getter. Ele não mexe nos dados do Estadio: cada objeto cuida do que é seu (encapsulamento).
Estadio maracana = new Estadio("Maracanã", 78000);
Time flu = new Time("Fluminense", maracana);
System.out.println(flu.descricao());
  • 1Cria primeiro a peça (Estadio).
  • 2Entrega a peça para o objeto maior.
  • 3Imprime Fluminense joga no Maracanã.

Cuidado com o null: se o estádio não foi informado, estadio.getNome() quebra com NullPointerException. Proteja no construtor: if (estadio == null) throw new IllegalArgumentException("Estádio obrigatório");

Quando usar: quando um dado tem vários campos ou comportamento próprio (endereço, estádio, técnico). Em vez de espalhar estadioNome, estadioCapacidade dentro do Time, crie a classe e componha. É o "tem um" do dia a dia.

Desafios

O que é um objeto composto?

Um objeto que herda de outroUm objeto que tem outros objetos como atributosUm objeto com muitos métodosTime tem Estadio: o Estadio é uma peça dentro do Time.

O estádio é null e o código chama estadio.getNome(). O que acontece?

Retorna texto vazioRetorna zeroLança NullPointerExceptionValidar no construtor evita esse erro.

7. Herança e polimorfismo

Herança: uma classe filha reaproveita tudo da classe pai. Goleiro é um Jogador, então herda nome e métodos, e ainda ganha o que é só dele.

public class Jogador {
    protected String nome;

    public String apresentar() {
        return nome;
    }
}

public class Goleiro extends Jogador {
    private int defesas;

    @Override
    public String apresentar() {
        return nome + " (Goleiro)";
    }
}

Linha a linha

  • 2protected: igual ao private, mas as classes filhas também enxergam.
  • 4-6Método do pai: devolve o nome.
  • 9extends = herda. Goleiro já nasce com nome e apresentar().
  • 10Atributo exclusivo do goleiro.
  • 12@Override avisa o compilador: "estou reescrevendo um método do pai". Se errar o nome, ele reclama.
  • 13-14A versão do goleiro, que troca o comportamento do pai.
Jogador j = new Goleiro();
j.apresentar();   // roda a versão do Goleiro
  • 1Variável do tipo pai guardando um objeto filho. Pode, porque todo Goleiro é um Jogador.
  • 2Java olha o objeto real e escolhe a versão certa. Isso é polimorfismo: mesma chamada, comportamentos diferentes.

Quando usar: herança quando a relação é "é um" e há código em comum. Polimorfismo quando você tem uma lista de tipos variados e quer tratar todos igual (um elenco com goleiros, zagueiros e atacantes).

Desafios

Qual palavra faz Goleiro herdar de Jogador?

Para que serve @Override?

Avisar que o método reescreve o do paiCriar um atributo novoDeixar o método privadoE o compilador confere se você acertou a assinatura.

O que é polimorfismo?

Esconder atributosCriar vários construtoresA mesma chamada se comportar diferente conforme o objeto realEx.: apresentar() responde diferente para Goleiro e Atacante.

8. Herança e polimorfismo a fundo

O que é: o filho reaproveita o pai e pode mudar seu comportamento (sobrescrita). Polimorfismo é tratar vários filhos como o pai e cada um responder do seu jeito.

Para que serve: não repetir código e evitar um monte de if por tipo.

public class Jogador {
    protected String nome;

    public Jogador(String nome) {
        this.nome = nome;
    }

    public double bonus() {
        return 1000;
    }
}

public class Atacante extends Jogador {
    private int gols;

    public Atacante(String nome, int gols) {
        super(nome);
        this.gols = gols;
    }

    @Override
    public double bonus() {
        return super.bonus() + gols * 500;
    }

    public double bonus(double extra) {
        return bonus() + extra;
    }
}

Linha a linha

  • 4-6O pai exige um nome para existir.
  • 17super(nome) chama o construtor do pai. Precisa ser a primeira linha do construtor do filho.
  • 21-24Sobrescrita: mesmo nome e mesmos parâmetros do pai, mas com cálculo próprio.
  • 23super.bonus() reaproveita o cálculo do pai (1000) e soma o extra do atacante. Nada de copiar código.
  • 26-28Sobrecarga: mesmo nome, parâmetros diferentes. Não substitui nada: é outra opção ao lado.
Sobrescrita (override)
Entre pai e filho. Mesma assinatura. Muda o comportamento herdado. Decidida na execução.
Sobrecarga (overload)
Na mesma classe. Parâmetros diferentes. Dá várias formas de chamar. Decidida na compilação.
List<Jogador> elenco = List.of(new Jogador("Zé"), new Atacante("Pedro", 20));
double total = 0;
for (Jogador j : elenco) {
    total += j.bonus();
}
if (elenco.get(1) instanceof Atacante a) {
    System.out.println(a.bonus(200));
}
  • 1Lista do tipo pai com um Jogador e um Atacante juntos.
  • 3-5A mesma chamada j.bonus() calcula 1000 para o Zé e 11000 para o Pedro. Cada objeto usa a sua versão: polimorfismo, sem nenhum if por tipo.
  • 6instanceof pergunta "é um Atacante?" e já cria a variável a (Java 16+), para acessar o que é exclusivo do filho.

Quando usar: sobrescrita quando o filho faz a mesma coisa de um jeito diferente. Sobrecarga quando a mesma ideia aceita entradas diferentes. instanceof só em último caso: se precisar dele toda hora, o polimorfismo não está sendo bem aproveitado. Evite hierarquias com mais de 3 níveis.

Desafios

Mesmo nome de método, parâmetros diferentes, na mesma classe. Como se chama?

9. Abstração, interface e composição

Abstrair é definir só o essencial e deixar os detalhes para quem implementa. Três ferramentas: classe abstrata, interface e composição.

public abstract class Jogador {
    public abstract String getPosicao();
}

public interface CobradorDePenalti {
    boolean cobrarPenalti();
}

public class Time {
    private List<Jogador> elenco = new ArrayList<>();

    public void contratar(Jogador j) {
        elenco.add(j);
    }
}

Linha a linha

  • 1abstract: ninguém pode fazer new Jogador(). Não existe "jogador genérico": todo jogador tem posição. Serve de base.
  • 2Método sem corpo: toda classe filha é obrigada a escrever o seu.
  • 5interface: um contrato de capacidade. Quem faz implements promete ter esses métodos.
  • 6Só a assinatura. Uma classe herda de um pai só, mas pode implementar várias interfaces.
  • 9-10Composição: o Time tem uma lista de Jogadores. List<Jogador> aceita só jogadores; ArrayList é uma lista que cresce sozinha.
  • 12-13contratar adiciona um jogador ao elenco.

Quando usar: classe abstrata para um conceito genérico com código compartilhado. Interface para uma capacidade que classes sem parentesco podem ter (bater pênalti). Composição é o padrão do dia a dia: se é "tem um", componha; se é "é um", herde.

Desafios

Quando usar classe abstrata?

Para um conceito genérico que não deve ser criado sozinhoPara guardar textoPara esconder atributosEla é uma base, não algo "concreto".

Qual a diferença entre herdar e implementar?

Uma classe herda de só uma classe, mas implementa várias interfacesInterface pode ser criada com newNão há diferençaPor isso interface é ótima para capacidades.

"Time tem uma lista de Jogadores" é um exemplo de:
