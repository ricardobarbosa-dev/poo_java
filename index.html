POO em Java

Passo 1 de 9

1. Classe e objeto

POO (Programação Orientada a Objetos) é organizar o código como o mundo real: em coisas que têm características e ações.

Classe = o molde (a planta de uma casa).

Objeto = a coisa criada a partir do molde (a casa construída).

De uma classe você cria quantos objetos quiser.

// Classe: o molde
public class Cachorro { }

// Objetos: criados com "new"
Cachorro rex  = new Cachorro();
Cachorro mel  = new Cachorro();

Aqui rex e mel são dois objetos diferentes, feitos do mesmo molde.

Pratique: pense em 3 classes do dia a dia (ex.: Carro, Aluno, Produto).

2. Atributos e métodos

Toda classe tem dois tipos de membros:

  • Atributos: o que o objeto tem (nome, idade). São variáveis.
  • Métodos: o que o objeto faz (latir, andar). São funções.
public class Cachorro {
    String nome;      // atributo
    int idade;        // atributo

    void latir() {   // método
        System.out.println(nome + " diz: Au au!");
    }
}

// Usando:
Cachorro rex = new Cachorro();
rex.nome = "Rex";
rex.latir();   // Rex diz: Au au!

O ponto (.) significa "do objeto": rex.nome é o nome do Rex.

Pratique: crie a classe Carro com modelo, velocidade e o método acelerar().

3. Construtor e this

No passo anterior, o objeto nasceu vazio e preenchemos depois. O construtor resolve isso: é um método especial que roda no new e já deixa o objeto pronto.

  • Tem o mesmo nome da classe.
  • Não tem tipo de retorno (nem void).
  • this = "este objeto aqui".
public class Cachorro {
    String nome;
    int idade;

    Cachorro(String nome, int idade) {
        this.nome  = nome;   // atributo = parâmetro
        this.idade = idade;
    }
}

Cachorro rex = new Cachorro("Rex", 3);

Sem o this, nome = nome não saberia qual é o atributo e qual é o parâmetro.

Pratique: adicione um construtor ao Carro que receba o modelo.

4. Encapsulamento

Ideia: proteger os dados do objeto. Ninguém de fora deve mexer direto no saldo da sua conta; só por operações controladas.

Como fazer: atributos private + métodos públicos (getters para ler, setters para alterar com regras).

public class Conta {
    private double saldo;

    public double getSaldo() { return saldo; }

    public void depositar(double valor) {
        if (valor > 0) {      // regra protegida
            saldo += valor;
        }
    }
}

conta.saldo = -999;      // ERRO: é private
conta.depositar(100);    // OK
Modificadores de acesso:
private só a própria classe · protected classe, pacote e filhas · public todo mundo · (sem nada) mesmo pacote.

5. Herança

Uma classe pode herdar atributos e métodos de outra, evitando código repetido. Relação "é um": Cachorro é um Animal.

public class Animal {
    protected String nome;
    Animal(String nome) { this.nome = nome; }
    void comer() { System.out.println(nome + " come"); }
}

public class Cachorro extends Animal {
    Cachorro(String nome) {
        super(nome);   // chama o construtor do pai
    }
    void latir() { System.out.println("Au!"); }
}

Cachorro rex = new Cachorro("Rex");
rex.comer();   // herdado de Animal
rex.latir();   // próprio
  • extends cria a herança.
  • super acessa a classe pai.
  • Java só permite um pai por classe.

6. Polimorfismo

"Muitas formas": o mesmo comando faz coisas diferentes dependendo do objeto. Duas faces:

a) Sobrescrita (@Override)

O filho reescreve um método do pai.

class Animal {
    void som() { System.out.println("..."); }
}
class Cachorro extends Animal {
    @Override void som() { System.out.println("Au!"); }
}
class Gato extends Animal {
    @Override void som() { System.out.println("Miau!"); }
}

Animal a = new Cachorro();   // pai guarda filho
a.som();   // Au!  (decide em tempo de execução)

b) Sobrecarga (overload)

Mesmo nome, parâmetros diferentes, na mesma classe.

int somar(int a, int b) { return a + b; }
double somar(double a, double b) { return a + b; }

Pratique: crie Vaca com som "Muuu" e monte um array de Animal com 3 bichos, chamando som() em cada um.

7. Abstração: abstract e interface

Abstrair é mostrar só o essencial. Às vezes a classe pai é uma ideia genérica demais para existir sozinha (não existe "um animal qualquer").

Classe abstrata

Não pode ser instanciada; pode ter métodos prontos e métodos sem corpo que os filhos devem implementar.

abstract class Animal {
    abstract void som();            // sem corpo
    void dormir() { System.out.println("zzz"); }
}
// new Animal();  → ERRO

Interface

Um contrato: "quem assina, tem que ter estes métodos". Uma classe pode implementar várias.

interface Voador { void voar(); }
interface Nadador { void nadar(); }

class Pato extends Animal implements Voador, Nadador {
    public void som()   { System.out.println("Quack"); }
    public void voar()  { System.out.println("voando"); }
    public void nadar() { System.out.println("nadando"); }
}
Como escolher: relação "é um" com código compartilhado → classe abstrata. Capacidade ("sabe voar") → interface.

8. static e final

static: pertence à classe, não ao objeto

Existe uma só cópia, compartilhada. Dá para usar sem criar objeto.

class Aluno {
    static int total = 0;     // compartilhado
    Aluno() { total++; }
}
new Aluno(); new Aluno();
System.out.println(Aluno.total);   // 2

Math.sqrt(16);   // método static: sem new Math()

final: não muda mais

  • Variável final: constante.
  • Método final: não pode ser sobrescrito.
  • Classe final: não pode ser herdada (ex.: String).
static final double PI = 3.14159;

9. Juntando tudo

Um mini sistema bancário usando os 4 pilares:

abstract class Conta {
    private double saldo;           // encapsulamento
    public double getSaldo() { return saldo; }
    public void depositar(double v) { if (v > 0) saldo += v; }
    protected void debitar(double v) { saldo -= v; }
    public abstract void sacar(double v);   // abstração
}

class Corrente extends Conta {    // herança
    @Override public void sacar(double v) {  // polimorfismo
        if (getSaldo() + 500 >= v) debitar(v);  // cheque especial
    }
}
class Poupanca extends Conta {
    @Override public void sacar(double v) {
        if (getSaldo() >= v) debitar(v);
    }
}

Conta c = new Poupanca();
c.depositar(200);
c.sacar(50);

Resumo dos 4 pilares

Encapsulamento
Esconder dados com private e expor só o necessário.
Herança
Reaproveitar código com extends.
Polimorfismo
Mesmo método, comportamentos diferentes por objeto.
Abstração
Definir o essencial com abstract e interface.
